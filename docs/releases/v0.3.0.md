whichphp v0.3.0 judges the builds of packagers that backported the PHP2Shell fixes by the packagers' own fixed releases, and finds PHP it missed before on cPanel and CloudLinux. Some verdicts change; if a script or CI gate reads whichphp's results, read [Verdicts that change](#verdicts-that-change). The GitHub Action works the same as in v0.2.0.

### What's new

- **Packagers that backport.** PHP 8.1 and older got no upstream fix, but several packagers backported it while keeping the old version, so `php -v` and version checks can't tell their fixed builds from unfixed ones. whichphp now recognizes each packager's builds in the package database and compares the package release with the first fixed release the packager itself published:
  - **Ondřej Surý** (ppa:ondrej/php and packages.sury.org): 5.6 to 8.1.
  - **Remi**: 7.4, 8.0 and 8.1 on EL8 to EL10 and Fedora; 7.2 and 7.3 on EL8.
  - **cPanel** (EasyApache 4): ea-php74, ea-php80 and ea-php81.
  - **CloudLinux**: alt-php 5.4 to 8.5, and its own builds of cPanel's ea-php.
  - **TuxCare** Extended Lifecycle Support: the distro's own PHP on CentOS, RHEL and Oracle Linux 7, CloudLinux 7, Amazon Linux 2, CentOS 8, AlmaLinux 9 ESU, Debian 10 and 11 and Ubuntu 16.04 to 20.04, and alt-php for Debian and Ubuntu.
  - **Freexian Extended LTS**: Debian 9, 10 and 11.

  A build at or above its packager's first fixed release gets the new verdict `FIXED_BY_VENDOR_BACKPORT` (OpenVEX `fixed`, no SARIF result, exit 0). A backporting packager's build that whichphp has no data for gets `NEEDS_VENDOR_CONFIRMATION` (exit 2), or `VULNERABLE_EOL` for an end-of-life branch in an image created before the fix. The data is [`internal/advisory/packagers.csv`](https://github.com/yusufyildiz34/whichphp/blob/main/internal/advisory/packagers.csv): 87 rows (77 first fixed releases and 10 branches with no fix), each with the packager's own advisory, changelog or repository as its source, all checked a second time against the packagers' repository metadata, errata and VEX files.
- **GetPageSpeed** builds are recognized by the rpm Vendor tag. Its own pages give conflicting first fixed releases, so it has no rows yet, and its end-of-life branches get `NEEDS_VENDOR_CONFIRMATION`.
- **Packager data from you.** The [packager data template](https://github.com/yusufyildiz34/whichphp/issues/new?template=packager-data.yml) and [CONTRIBUTING](https://github.com/yusufyildiz34/whichphp/blob/main/CONTRIBUTING.md#adding-packager-data) say what a new row needs.

### Verdicts that change

- **cPanel and CloudLinux builds are found.** Syft doesn't list a PHP binary that an OS package owns, and whichphp didn't know the `ea-phpNN-php-*` and `alt-phpNN-*` package names, so a cPanel or CloudLinux system or image with only those read **NO PHP (exit 0)**. They now get verdicts.
- **packages.sury.org builds are Sury's.** Their versions (`8.3.35-1+0~20261001.55+debian12~1.gbp1a2b3c`) don't contain `deb.sury.org`, so they were taken for Debian's own packages, and an unfixed 8.3.35 could read `FIXED_BY_DISTRO_BACKPORT`. They are now judged as Sury's.
- **Backports into end-of-life branches** from Sury and Remi read `FIXED_BY_VENDOR_BACKPORT` instead of `VULNERABLE_EOL`. Their builds before the fix read `VULNERABLE`.
- **Debian 9 to 11:** Freexian's fixed builds read `FIXED_BY_VENDOR_BACKPORT`; older builds in an image created after the fix read `VULNERABLE_EOL` instead of `UNKNOWN`.
- **CentOS 7, 8 and Stream 8 are end-of-life.** They counted as "support unknown", so a package Grype had no match for could read `FIXED_BY_DISTRO_BACKPORT`. Now it reads `UNKNOWN`, or `VULNERABLE_EOL` in an image created before the fix.
- **A placeholder creation date isn't a date.** Reproducible builds set an image's creation date to 1970 or 1980, which counted as "built before the fix". A date before 2013 is now ignored.

### Fixes

- `whichphp cluster` could label a verdict it didn't recognize "fixed" in its table. It now reads "unknown".

### Limits

- TuxCare's Alpine builds are fixed, but whichphp has no apk version order yet, so they read `NEEDS_VENDOR_CONFIRMATION`.
- GetPageSpeed and CloudLinux's own system PHP have no rows yet.
- cPanel's ea-php73 and older read `VULNERABLE_EOL` with "cPanel published no fix". cPanel has unreleased fixes for them; the table changes when they ship.
- The table is as current as its last check (November 1, 2026). A packager that ships a fix for a branch listed as having none shows as vulnerable until the table is updated.

### Verify your download

```sh
sha256sum --ignore-missing -c SHA256SUMS        # on macOS: shasum -a 256 --ignore-missing -c SHA256SUMS
gh attestation verify whichphp_0.3.0_linux_amd64.tar.gz --repo yusufyildiz34/whichphp \
  --signer-workflow yusufyildiz34/whichphp/.github/workflows/release.yml --bundle whichphp_0.3.0.sigstore.json
```
